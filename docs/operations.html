voidgatectl

Command Effect
status state, armed, rx_pps, rx_bps, drop count, iface
stats XDP counters: rx_pkts, passed, dropped, non_ip, map_full, parse_err
drops installed prefixes with reason and age
arm cfg.armed = 1; re-baseline remote rate snapshots
disarm flush drop_*, cfg.armed = 0, back to IDLE
drop <cidr> manual insert; forces ACTIVE. Reason 1. Not auto-expired.
drop <cidr> ttl=<sec> timed insert for OpenResty bans; forces ACTIVE. Reason 4. Lifted after ttl (1 s to one year); a re-ban only extends it. Never upgrades a manual drop and never counts toward aggregate_k.
undrop <cidr> remove one prefix from the drop tree
reload re-read the config file; replace allow/local maps and ports
reload does not change the attached interface, XDP mode, map sizes, log or pid file, or the metrics listener. Those are fixed at start. Reload does lift any installed drop, manual ones included, that now covers a local_* or allow_* prefix.

Drop reasons: 1 manual, 2 policy, 3 aggregate.

Config

One key = value per line; # starts a comment. Every key is optional, and the defaults below are also what ships in configs/voidgate.conf. The commented file explains each one in more depth.

Key Default What it does reload
Interface and files

xdp_mode auto auto tries native driver XDP, then SKB. native / skb pin one. restart
log_file /var/log/voidgate.log Append-only log, with -d only; under the unit the log is the journal. Parent directory must exist. restart
pid_file /run/voidgate.pid Locked for the daemon's life; -s stop reads it. restart
Waking up

wake_mbps 25 Aggregate NIC Mbit/s that arms the gate. Either wake_* arms. live

clear_seconds 30 Quiet seconds, with an empty drop tree, before ACTIVE → IDLE. live
Dropping

OpenResty client

voidgate is not a WAF. Let OpenResty, or a gateway built on it such as Kong or APISIX, decide who is abusive and push that address down to XDP with a timed drop. lua/resty/voidgate.lua talks to the socket over a non-blocking cosocket. Install it with sudo make install-lua (OpenResty's site lualib, or set LUA_DIR), and add the worker user to the group voidgate, which the shipped unit gives the socket to with -g voidgate, so nginx can reach it: commonly nobody for OpenResty, kong for Kong, and nobody or apisix (Docker image) for APISIX.

nginx 
lua_shared_dict voidgate_ban 1m;

location / {
    limit_req zone=api burst=20 nodelay;
    limit_req_status 429;
    log_by_lua_block {
        if ngx.status == 429 then
            require("resty.voidgate").ban(ngx.var.remote_addr, 600,  -- 10m
                                          { dict = "voidgate_ban" })
        end
    }
}

ban(ip, ttl, opt) works from every phase but init_by_lua*, log included, and sends one ban per address per window. ban_now(ip, ttl) sends at once and returns the daemon's answer, in rewrite, access, content or timer context. Every drop from Lua needs a ttl: a permanent drop is voidgatectl drop's job. The other methods (status(), stats(), drops(), drop(cidr, ttl), undrop(), arm(), disarm(), reload()) run in rewrite, access, content or timer context and return nil, err on failure. stats() returns 64-bit counters as decimal strings.

Ban only real peers. Behind a CDN or load balancer, put the proxy ranges in allow_networks, or a forged client-IP header can ban your own front door. Any drop keeps the gate armed until it lifts.

ACTIVE policy, short

Each tick, remotes over threshold become /32 or /128. Dense clusters become /24 or /64. Userspace will not install a prefix that covers the VM itself or the allow list. On disarm, remote_* stays; the next arm re-baselines snapshots so leftover counters are not a phantom flood.

A remote source port of 22 is not SSH. Only the local side of allow_ports is whitelisted. Do not drop the interface CIDR.
