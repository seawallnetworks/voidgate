voidgatectl

Command Effect
status state, armed, rx_pps, rx_bps, blocked, iface
stats [<interval> [<count>]] XDP counters only (the state is status's); voidgatectl stats reads both and prints one row: rx_pkts, passed, dropped, then map_full= and parse_err= when not 0 (non_ip and reply_passed only in -r stats). With an interval, the same row every interval seconds, its rx_pps, rx_bps, drop%, map_full and parse_err over the interval, and, after count rows, an Average: row (none on Ctrl-C), as mpstat. -r stats: the daemon's key=value answer
blocks [after <id>] what is blocked, oldest first, 256 a page: id, cidr, reason, inserted, expires. voidgatectl blocks reads every page and prints a table; -r blocks the daemon's page
arm cfg.armed = 1; re-baseline remote rate snapshots
disarm lift every block (flush drop_*), cfg.armed = 0, back to IDLE
block <cidr> manual insert; forces ACTIVE. Reason 1. Not auto-expired.
block <cidr> ttl=<sec> timed insert for OpenResty bans; forces ACTIVE. Reason 4. Lifted after ttl (1 s to one year); a re-ban only extends it. Never upgrades a manual block and never counts toward aggregate_k.
unblock <cidr> lift one block
reload re-read the config file; replace allow/local maps and ports
reload does not change the attached interface, XDP mode, map sizes, log or pid file, or the metrics listener. Those are fixed at start. Reload does lift any installed block, manual ones included, that now covers a local_* or allow_* prefix.

Drop reasons: 1 manual, 2 policy, 3 aggregate.

Config

One key = value per line; # starts a comment. Every key is optional, and the defaults below are also what ships in configs/voidgate.conf. The commented file explains each one in more depth.

OpenResty client

voidgate is not a WAF. Let OpenResty, or a gateway built on it such as Kong or APISIX, decide who is abusive and push that address down to XDP with a timed block. lua/resty/voidgate.lua talks to voidgate over a non-blocking cosocket. ban() and ban_now() use the ban socket, /run/voidgate-ban.sock, which takes only block <address> ttl=<seconds>, one address: a compromised gateway can't block a range, disarm the gate or lift a block. Install it with sudo make install-lua (OpenResty's site lualib, or set LUA_DIR), and add the worker user to the group voidgate_ban, which the shipped unit gives the ban socket to with -B voidgate_ban, so nginx can reach it: commonly nobody for OpenResty, kong for Kong, and nobody or apisix (Docker image) for APISIX.

nginx 
lua_shared_dict voidgate_ban 1m;

location / {
    limit_req zone=api burst=20 nodelay;
    limit_req_status 429;
    log_by_lua_block {
        if ngx.status == 429 then
            require("resty.voidgate").ban(ngx.var.remote_addr, 600,  -- 10m
                                          { dict = "voidgate_ban" })
        end
    }
}

ban(ip, ttl, opt) works from every phase but init_by_lua*, log included, and sends one ban per address per window. ban_now(ip, ttl) sends at once and returns the daemon's answer, in rewrite, access, content or timer context. Every block from Lua needs a ttl: a permanent block is voidgatectl block's job. The other methods (status(), stats(), blocks(), block(cidr, ttl), unblock(), arm(), disarm(), reload()) run in rewrite, access, content or timer context and return nil, err on failure. stats() returns 64-bit counters as decimal strings. They use the control socket, /run/voidgate.sock (group voidgate), the whole protocol: join it only a program that needs that.

Upgrading from a voidgate without the ban socket: a worker user that joined voidgate can't reach the ban socket, and every ban fails with only a line in nginx's error log. Add it to voidgate_ban, restart the gateway, then take it out of voidgate.
Ban only real peers. Behind a CDN or load balancer, put the proxy ranges in allow_networks, or a forged client-IP header can ban your own front door. Any block keeps the gate armed until it lifts.

ACTIVE policy, short

Each tick, remotes over threshold become /32 or /128. Dense clusters become /24 or /64. Userspace will not install a prefix that covers the VM itself or the allow list. On disarm, remote_* stays; the next arm re-baselines snapshots so leftover counters are not a phantom flood.

A remote source port of 22 is not SSH. Only the local side of allow_ports is whitelisted. Do not drop the interface CIDR.
